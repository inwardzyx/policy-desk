## 项目一：制度问答台 —— 三层架构的企业问答系统（个人项目，2026.10–11）

> 一句话：Vue3 → Spring Boot → Python 算法服务。**按「谁在问、能问什么、问了多少次」分层**，
> 而不是把所有逻辑塞进一个服务。

- **前端**：Vue 3 + TS 实现登录 / 问答 / 文档三页；开发期用 Vite 代理、生产用 Nginx 同源反代，
  不为开发便利在网关上开跨域口子。
- **后端**：Spring Boot 3 + MyBatis-Plus + MySQL 承载用户、角色、审计；JWT(HS256，密钥 ≥32 字节) + BCrypt(10)；
  算法服务通过 `/internal/*` 与内部口令隔离，未配置口令或认证模式为 none 时直接 503（fail-closed）。
- **权限（核心）**：角色→ACL 单向投影（employee→public / hr→hr,public / 未知角色 403 不降级）。
  实测同一问题：hr 命中「加班与补贴」并带原文引用，employee 明确拒答；而 employee 问「年假」可正常回答——
  **差别只来自令牌里的角色**，请求体、URL、参数不变。
- **配额**：Redis `INCR` + 按天 `TTL` 实现每人每日额度，在**调用模型之前**判定；
  第 3 次超限返回 429 + `Retry-After`，不产生任何 token 费用。
- **审计**：每次问答落库，问题只存 SHA-256（可比对频次、还原不出原文），
  记录 answered / refused / quota_denied / upstream_error 四类决策，`trace_id` 与算法服务对齐。
- **质量与交付**：63 条后端测试（H2 内存库，不依赖本机 MySQL）+ 4 条前端测试 + GitHub Actions 三 job；
  Actuator 健康检查含上游探针（AI 不可用时整体 DOWN，实测 503）；
  Docker Compose 编排 web / api / ai / mysql / redis 五容器（全 healthy），
  Nginx 上传上限与后端 20MB 对齐；公网经 Tunnel 可访问，问答端到端 ≈4.0s。

## 面试口径（不在简历里，背下来）

**"这项目最难的地方是什么？"**
> 不是把三层拼起来，是"权限怎么穿过去"。检索在 Python 里，身份在 Java 里，
> 如果每层各判一次权限，迟早有一层漏。所以我把"角色→ACL"做成**单向投影**，
> 只有一处转换，下游只认 ACL 不认角色。未知角色直接 403 不降级——**宁可拒绝，也不要猜**。

**"为什么配额放在 Java 而不是算法服务？"**
> 因为它必须在**调用模型之前**判定。放 Java，超额请求根本打不到 Python，也就不烧 token；
> 放 Python，得先跑一遍检索甚至改写才可能被拒。而且计数要跨进程一致，Java 侧接 Redis 更自然。

**"为什么前端不用组件库？"**
> 三个页面，引一个 200KB 的库还要配按需引入，换来的收益我看不见。
> 等页面到十个以上、或者要做复杂表格/表单校验，我会换——那时它是省事，现在它是负担。

**"这套东西你自己觉得哪里还不成熟？"**
> 两处。一是 JWT 签发后无法立刻撤销（120 分钟有效期内改权限不生效），
> 正确做法是给用户加 `token_version`，令牌里带版本、改权限时 +1，而不是存黑名单。
> 二是配额"先扣再判"，上游失败不退——这是有意的（补偿需要幂等键，复杂度高于收益），
> 但这条取舍我写在文档里，没藏在代码里。
