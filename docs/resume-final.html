我的工作
  • 指标与口径：3 条检索层指标（Recall@5 / 漏答 / 拒答准确），分母各自算；口径只写一处， 报告全脚本生成、数字不手抄，改一个跑批 JSON 报告就跟着变。

  • 先量噪声，再谈差异：同配置重跑 4 次得观测极差（Recall@5 ±1 / 漏答 0 / 拒答 ±1）， 小于等于该幅度不作解释；改动一律用 exact McNemar 配对检验 判定。
  • 门禁与自证：每条判据配一条变异用例（改 k、改比对字段、把指标写反）证明它会红； 跨层直接拒绝比较；κ 在样本 <20 时拒绝输出。
  • 可追溯：每份报告带运行指纹（git sha + 逐目录语料哈希 + 依赖指纹 + 可用 PDF 后端）； 报告过期合法，「引用过期报告」才报红 —— 这一条把「README 与产物一起过期」也堵住了。

制度问答台 —— 企业制度问答系统（被测对象）2026.09 – 2026.11

员工用自然语言提问，答案下方带原文条款出处；资料里没有就明确拒答、不编造。 按「谁在问、能问什么、问了多少次」拆成 Java 业务层与 Python 算法层。
关键实现
  • 权限：角色在业务层一次性投影成 ACL（未登记角色直接 403、不降级），算法层只认 ACL。 实测同一问题：人事命中薪酬条款并带出处，普通员工被明确拒绝，请求参数一个字没变。
  • 检索与成本：向量 + BM25 + RRF + LLM 精排；条款号写进索引后条款类命中 2/15 → 13/15。 每日配额在调模型之前判定，超限 429 且不产生模型费用。
  • 结果：63 条后端 + 4 条前端 + 473 条算法层测试；五容器一条命令起、公网可访问，一次问答约 4 秒。
