制度问答台 —— 分层架构的企业问答系统个人项目 · 2026.09 – 2026.11

Vue 3 + TS + Vite ｜ Spring Boot 3 + MyBatis-Plus ｜ MySQL / Redis ｜ Python + FastAPI + bge-small-zh / BM25 / RRF / DeepSeek ｜ Docker Compose + Nginx
把 10 份校级制度做成「答案带条款出处、库里没有就当场拒答」的问答系统， 并按「谁在问、能问什么、问了多少次」拆成业务层与无状态算法层，两层各自可独立测试与替换。
  • 分层与配额：前端 → Java 业务层（用户 / 角色 / 配额 / 审计）→ 算法层（检索 / 精排 / 生成）。 配额在调用模型之前判定，超额请求零 token 消耗（429 + Retry-After）； 实测问答端到端 ≈ 4.0 s，检索 p50 3.1 ms / p95 7.6 ms（含向量编码，n=240）。
  • 权限（核心）：角色 → ACL 单向投影（employee → public；hr → hr, public；未登记角色 403 不降级）， 身份只解析一次、下游只认 ACL。实测同一问题：hr 命中「加班与补贴」并带原文引用，employee 明确拒答； 而 employee 问「年假」可正常回答 —— 差别只来自令牌里的角色。
  • 入库把关：286 块原始材料 → 放行 263 / 拦下 23，每条理由可在 /guard-report 逐条查； 近似重复阈值 0.96 是量出来的（最像的一对合法条款 0.9230、该拦的同义改写 0.9839，两簇之间是空的）。
  • 不编造：精排最高分 < 5 直接返回「我不编」、不调用生成模型；精排挂掉时降级走粗捞并标 rerank_used=false，故障不伪装成「库里没有」。
  • 评测：双评测集（调参集 + 105 题盲出独立集，与调参集零重合）； Recall@5 44/44、漏答率 4/44 → 1/44（exact McNemar p = 0.0156）； 另有三条「看起来更好」的改法被同一门禁在 39 题上同时否决、全部不动。
  • 工具与交付：自写 MCP server / client（手写 JSON-RPC over stdio，不依赖官方 SDK）， 把 search_policy 从借道 /chat 改到 /search，配对 A/B 证明渲染文本逐字节一致、每次省 ≈ 366 token； 63 条后端测试 + 4 条前端测试 + GitHub Actions 三 job；Compose 编排五容器、Nginx 反代、公网 Tunnel 可达。
