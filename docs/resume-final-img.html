制度问答 Agent：多步检索 + 过程可见的问答系统（独立开发）2026.09 – 2026.11

面向学校与企业的制度问答系统。员工用自然语言提问，Agent 自己决定查几次、查什么， 答案下方给出原文条款；库里没有资料时明确拒答。前端实时显示每一步的工具、参数、耗时和命中条数。
Vue 3 + TypeScript ｜ Spring Boot 3 + MySQL 8 + Redis ｜ Python + FastAPI + bge-small-zh / BM25 / RRF / DeepSeek ｜ MCP + SSE ｜ Docker Compose
项目详情
  • Agent 循环手写为 for rnd in range(rounds_limit)（默认 6 轮），每轮由模型选工具、 执行、结果回填消息序列；工具通过 MCP 以 JSON-RPC 运行在独立进程。另用 LangGraph 重写同一循环做对照， 控制流只差 3 处。
  • 拒答以原问题的过闸结果为准（gate）：模型改写问法后即使命中无关条款，也不推翻拒答结论。 修复前改写问法可绕过拒答，修复后拒答 26/61 → 40/61（同刻 /chat 41/61）。
  • 检索链路为 bge-small-zh 向量召回 + BM25 + RRF 融合 + 精排；上下文按八层拼装， 带 token 预算与 trace，超预算或撞上限时显式收尾，不静默截断。
  • SSE 同时穿过 FastAPI 与 Spring Boot 两层，Java 端只做字节转发；前端按事件渲染时间线， 16 条单测覆盖「算不算成功」的判定，缺 result 事件显示为状态未知。
  • 评测在 105 道盲出题上进行：先量噪声地板（±1 / 0 / ±1），再用 exact McNemar 判改动是否显著； 报告头记录代码、语料、依赖、判据四个版本，判据规则变更即判定旧报告失效。
  • 交付为 Docker Compose 五容器（web / api / ai / mysql / redis），Nginx 反向代理与上传限额， Cloudflare Tunnel 对外；两仓 CI 覆盖后端、前端、容器与评测门禁，均通过。
成果：gold 条款命中 42/44 · 拒答 40/61 · 与同刻 /chat 打平（1 胜 2 负，差异在噪声带内）
一次问答约 5 秒、2 步工具调用 · 测试 63 条后端 + 16 条前端 + 541 条算法层
