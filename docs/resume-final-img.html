项目背景：制度散落在几十份文档里，员工查一次要翻很久；通用大模型回答没有出处、容易编。 产品：Agent 自己决定查几次、查什么，答案给原文条款，查不到就明确拒答，前端时间线显示每一步。
Vue 3 + TypeScript ｜ Spring Boot 3 + MySQL 8 + Redis ｜ Python + FastAPI + bge-small-zh / BM25 / RRF / DeepSeek ｜ MCP + SSE ｜ Docker Compose
项目详情
  • 工具调用：循环手写为 for rnd in range(rounds_limit)（默认 6 轮）， 模型选工具 → 执行 → 结果回填；工具走 MCP（JSON-RPC 独立进程），参数按 schema 校验， 失败按超时 / 参数 / 权限归因；另用 LangGraph 重写做对照，控制流只差 3 处。
  • 拒答：以原问题的过闸结果为准，改写问法命中无关条款也不推翻； 修复前可绕过，修复后拒答 26/61 → 40/61（同刻 /chat 41/61）。
  • 检索与上下文：bge-small-zh 向量 + BM25 + RRF 融合 + 精排；上下文八层 + token 预算 + trace； 多轮会话保留最近 3 轮、更早截断（响应报 session_used），超预算显式收尾。
  • 受限执行：容器内跑代码（断网 / 只读 / 限内存 / 限进程），超时、OOM、联网、写盘 四类越界都实测拦截过；默认关闭，按需开启。
  • 流式与前端：SSE 穿过 FastAPI 与 Spring Boot 两层（Java 只转字节）；前端按事件渲染时间线， 16 条单测钉住「算不算成功」，缺 result 即判状态未知。
  • 评测与交付：105 题盲出集 + 9 套件 / 156 用例，先量噪声地板再上 exact McNemar， 能定位是检索、编排还是数据的问题；Docker 五容器 + Nginx + Tunnel，两仓 CI 覆盖后端 / 前端 / 容器 / 评测。
