## 一、做什么（一句话）

做一个**"AI 改动的发布平台"**：改 prompt / 换模型 / 调检索参数之后，
先自动跑一套评测题，达标才允许发布；发布按比例灰度；出问题一键回滚；谁改的、影响了谁都有记录。

**打个比方**：现在改 AI 就像"改完直接上线，出事重启"；
这个项目是给它加上**体检 + 试运行 + 一键撤销 + 病历本**。

---

## 二、为什么要做（真实问题）

我自己的项目里遇到过一次：评测的判分规则改了一版，之前跑的报告就全部作废了
（简历上引用的准确率数据当场失去可比性）。当时有三个问题答不上来：

1. 这次改动**会不会让线上效果变差**？（没有自动判断，只能人眼看几个问题）
2. 最近线上跑的是**哪一版**？（git 里几十个提交，说不清）
3. 出问题**怎么退回**、退到哪一版？（只能改代码 + 重启 + 重新验证）

这不是我一个人的问题，凡是做 AI 应用的团队都会遇到：**AI 的效果没法像代码那样"编译一下就知道对不对"**。

## 三、四个功能（这就是产品）

| 功能 | 说明 |
|---|---|
| 版本管理 | 每次改动存成一个版本（prompt 文本、模型名、检索参数），带创建人 |
| 评测门禁 | 版本提交后自动跑一套题，分数不达标就不允许发布 |
| 灰度发布 | 达标后先给 5% → 20% → 100% 的租户，**同一个租户看到的版本是稳定的** |
| 一键回滚 + 审计 | 出问题切回上一个达标版本；页面上能看到谁在什么时候发布/回滚了什么 |

## 四、加分点：这个项目练的是后端

它的业务是 AI，但技术全是后端，正好和我已有的项目互补：

| 技术点 | 用在哪 |
|---|---|
| 服务拆分（3 个 Java 服务 + 1 个 Python 执行器） | 配置服务 / 发布服务 / 调度门禁 / 评测执行器 |
| 消息队列（Redis Streams） | 发布后异步触发门禁，不阻塞用户操作 |
| 幂等（同一件事只做一次） | 消息重复投递时，门禁任务只跑一次 |
| 分布式锁 + 乐观锁 | 同一条配置不允许两个人同时发布 |
| 状态机 | 发布流程：待审核 → 门禁中 → 灰度中 → 已发布 / 已回滚 |
| 超时与降级 | 评测服务卡住时，发布接口不能被拖死 |
| 日志追踪 | 一次发布能在 4 个服务的日志里串起来 |

**为什么不做电商/点评类**：那些题目面试官一眼就认出来（网上有现成教程），
而且和我找的 AI 方向不对口。这个题目目前没人做，能讲出我自己的设计取舍。
