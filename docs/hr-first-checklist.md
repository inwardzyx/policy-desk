# HR 优先清单（简历是给 HR 看的，不是给面试官看的）

> 用户 2026-11-18 的判断：**简历很大程度上是让 HR 开心，只有这样才能漏到面试官。**
> 这句话是对的，但要拆成"HR 到底在开心什么"——否则容易滑成吹牛，反而在面试官那关崩。

## 一、HR 的"开心"具体是五件事

| HR 想要的 | 你的做法 | 在哪体现 |
|---|---|---|
| **3 秒能判断你做什么** | 求职意向 + 项目首句写"谁用、解决什么" | 抬头 + 简介 |
| **关键词能搜到** | Agent / MCP / RAG / FastAPI / 评测 / CI 全在技能栏 | 专业技能 |
| **会干活，不是只会学** | 数字：42/44、40/61、541 条测试、CI 均绿 | 成果块 |
| **没有风险信号** | 到岗时间写死、学历写清、仓库可点 | 抬头 + 其他 |
| **格式像正式简历** | 一页、无错别字、PDF、文件名规范 | 全文 |

**"开心"不等于"夸自己"**：HR 讨厌的是"精通/熟练掌握/学习能力强"，喜欢的是"能立刻判断、没有意外"。

## 三、投递时的"HR 友好"细节

| 项 | 该怎么做 |
|---|---|
| PDF 文件名 | `周语昕-AI应用开发实习.pdf`（不要 `resume-final.pdf`） |
| 邮件主题 | `应聘 AI 应用开发实习-周语昕-可立即到岗` |
| 附件 | 只发 PDF；不要 PNG/JPG（ATS 提取不到文字） |
| 正文 | 3 行以内 + 一句"方便的话我可以先发两个仓库链接" |
| 在线简历 | 期望岗位 / 到岗时间 / 个人优势第一行，三处必须和 PDF 一致 |

## 四、一句话原则

> **对 HR 要"好判断"，对面试官要"经得起问"。**
> 两者冲突时，先满足 HR（否则你见不到面试官）；但**不能靠编**——因为面试官会当场验证。
